# 프론트 패턴

FORMA 프론트 컴포넌트(FormaForm/Grid/Tab/Modal 등)로 화면을 짤 때의 **관례**. API 시그니처 자체는 `doc/FormaForm-위젯-레퍼런스.md`에 있고, 이 문서는 "어떻게 조립하는가"를 다룬다.

---

## 1. 화면 HTML 1파일 원칙

한 화면 = HTML 1파일(인라인 `<script>`). 별도 .js 파일 없음. 스크립트 로딩 순서:

```html
<script src="/assets/js/framework/forma.core.js"></script>
<script src="/assets/js/framework/forma.popup.js"></script>
<script src="/assets/js/framework/forma.util.js"></script>
<script src="/assets/js/framework/forma.grid.js"></script>
<script src="/assets/js/framework/forma.form.js"></script>
<script src="/assets/js/framework/forma.toolbar.js"></script>
<script src="/assets/js/framework/forma.tab.js"></script>
<script src="/assets/js/framework/forma.modal.js"></script>
```

## 2. IIFE 스켈레톤

모든 화면이 동일 구조:

```javascript
(function() {
    const PGM = 'CST010';
    const listener = platform.initListener(PGM);
    const ctx = {};

    listener.initPgm = function() {
        ctx.searchForm = new FormaForm('#search-area', { search: true, elements: [...] });
        ctx.grid1 = new FormaGrid('#grid-area', { editable: true, checkable: true, columns: [...] });
        listener.button.search.click();           // 진입 시 자동 조회
    };

    listener.button.search.click = async function() {
        const result = await platform.post('/' + PGM.toLowerCase() + '/selectGrid1',
                                           ctx.searchForm.getData());
        if (result.resultCode === RESULT_CODE.OK) {
            ctx.grid1.setData(result.resultData);
        }
    };

    listener.button.save.click = async function() {
        const data = ctx.grid1.getModifiedData();
        if (data.length === 0) {
            FormaPopup.toast.info('변경된 행이 없습니다.');
            return;
        }
        if (!ctx.grid1.checkGridValidation()) return;
        if (!await FormaPopup.confirm.show(data.length + '건 저장하시겠습니까?')) return;
        const result = await platform.post('/' + PGM.toLowerCase() + '/saveGrid1', data);
        if (result.resultCode === RESULT_CODE.OK) {
            FormaPopup.toast.success('저장되었습니다.');
            listener.button.search.click();
        }
    };

    document.addEventListener('DOMContentLoaded', () => platform.startPage(PGM, listener));
})();
```

`platform.startPage(PGM, listener)`가 내부에서:
1. `GET /api/pgm/{PGM}/init` 호출 → pgmInfo, pgmAuth 획득
2. `FormaToolbar.render('#forma-toolbar', {listener, pgmInfo, pgmAuth})` — 권한 기반 버튼 + 단축키 자동 등록
3. `listener.initPgm()` 실행

개발자는 `listener.button.{search|news|save|del|print|init|upload|etc1~10}.click`만 채우면 된다.

## 3. Listener 이벤트

| 카테고리 | 이벤트 | 파라미터 |
|---|---|---|
| button | search/news/save/del/print/upload/init.click | — |
| button | etc1~etc10.click | — |
| button | `*.show()` / `*.hide()` | 런타임 토글 |
| gridRow | click | (record, grid, col) |
| gridRow | dblclick | (rowId, colId, record, grid) |
| gridEditor | changed | (grid, state, editor) |
| gridEditor | beforeEditStart | (grid, record, curCol) → return true/false |
| treeGridRow | click / dblclick | 동일 |
| tabBar | tabChange | (tab) |
| editor | change | (el) |
| editor | keydown | (el, event) |

## 4. 화면 유형별 레이아웃

### 4.1 list — 단순 목록
```html
<div class="forma-page">
    <div class="forma-page-header">
        <h1 class="forma-page-title">{화면명}</h1>
        <div id="forma-toolbar"></div>
    </div>
    <div class="forma-content">
        <div id="search-area"></div>
        <div id="grid-area"></div>
    </div>
</div>
```

### 4.2 split-detail — 좌우분할
```html
<div class="forma-content">
    <div id="search-area"></div>
    <div id="split-CST010" class="forma-split-h">
        <div id="grid1-area"></div>
        <div id="grid2-area"></div>
    </div>
</div>
<script>
    // initPgm 끝에:
    FormaUtil.initSplit('#split-' + PGM);
</script>
```
`onRowClick(grid1)` → `platform.post('/xxx/selectGrid2', {pk}, ...)` → `ctx.grid2.setData(...)`.

### 4.3 master-detail — 상하 마스터-디테일
```html
<div class="forma-content">
    <div id="search-area"></div>
    <div id="master-grid"></div>
    <div id="detail-form" style="display:none"></div>
    <div id="detail-grid"></div>
</div>
```
마스터 행 클릭 시 `detail-form` 표시 + `detail-grid` 로드.

### 4.4 split-tab — 좌우분할 + 탭
```html
<div id="split-CST010" class="forma-split-h">
    <div id="grid1-area"></div>
    <div id="tab-area"></div>
</div>
<script>
    ctx.tab = new FormaTab('#tab-area', {
        tabs: [{id: 'tab-basic', label: '기본정보'}, {id: 'tab-detail', label: '상세'}],
        listener: listener
    });
    ctx.basicForm = new FormaForm(ctx.tab.getContentEl('tab-basic'), {...});
    ctx.detailGrid = new FormaGrid(ctx.tab.getContentEl('tab-detail'), {...});
    FormaUtil.initSplit('#split-' + PGM);
</script>
```

## 5. 서버 페이징

대량 데이터(1000건+)는 서버 페이징. `onPageChange` 콜백으로 페이지 전환 시 서버 재호출.

```javascript
ctx.grid1 = new FormaGrid('#grid-area', {
    paging: true, pageSize: 50,
    onPageChange: (page, size) => loadGrid1(page, size)
});

async function loadGrid1(page, size) {
    const result = await platform.post('/' + PGM.toLowerCase() + '/selectGrid1', {
        ...ctx.searchForm.getData(),
        page, pageSize: size
    });
    ctx.grid1.setData(result.resultData.data, result.resultData.totalCount);  // totalCount 필수
}
```

Controller는 `{page, pageSize}`를 받아 `_offset`을 계산 후 `{data, totalCount}` Map 반환.

## 6. 저장·삭제 플로우 관례

**저장**:
1. `getCheckedData()` 또는 `getModifiedData()`로 데이터 수집
2. 빈 배열 체크 → `FormaPopup.toast.info('변경된 행이 없습니다.')`
3. `checkGridValidation()` — required 컬럼 검증
4. `FormaPopup.confirm.show(n + '건 저장하시겠습니까?')` await
5. 성공 → `FormaPopup.toast.success()` + 재조회

**삭제**:
1. `getCheckedData()` 또는 `getSelectedItem()`
2. `FormaPopup.confirm.show(n + '건 삭제하시겠습니까?')`
3. 성공 → 재조회

## 7. 공통 팝업 연동 (codePopup)

FormaForm의 `codePopup` 위젯으로 거래처·품목·사용자 선택:

```javascript
{
  field: 'cust_cd', label: '거래처', widget: 'codePopup',
  popup: {
    url: '/pages/popup/CUS_P01.html',
    codeField: 'CUST_CD', nameField: 'CUST_NM',
    width: 800, height: 600
  }
}
```

팝업 내부에서는 `FormaModal.current().ok({CUST_CD: 'C001', CUST_NM: '...'})`로 결과 반환.

## 8. CSS 네임스페이스

- 전역 태그 스타일 금지 (e.g. `button { ... }`). 모든 커스텀은 `.forma-*` 접두.
- 테마 변수는 `forma.css`의 CSS 변수 활용. `var(--primary-color)` 등.
- 새 화면에서 인라인 `<style>`은 최소화하고 반드시 화면 고유 클래스(.cst010-xxx) 접두.

## 9. 용어 — widget / editor / type

FORMA 초기 설계 시점에 FormaForm과 FormaGrid가 따로 만들어지며 **같은 개념에 다른 이름**이 붙었다. 현재는 문서 규약으로 구분한다 (breaking change 없이).

| 대상 | 편집 위젯 지정 | 데이터 타입 / 기타 |
|---|---|---|
| FormaForm | **`widget`** (text/combo/date/currency/number/textarea/codePopup…) | — |
| FormaGrid | **`editor`** (text/select/combo/check/switch/date/currency/textarea) | `type`: number/text (정렬·align:right 힌트, **편집 위젯 아님**) |

### 규칙
- **FormaForm**에 `type: 'number'`는 **deprecated** — 대신 `widget: 'number'` 사용. 기존 코드는 동작하지만 신규 작성 금지.
- **FormaGrid**의 `type`과 **FormaForm**의 `type`은 같은 키워드지만 역할이 전혀 다르다. 혼동 주의.
- **같은 편집 위젯**을 Form/Grid에 둘 다 올릴 때: Form은 `widget: 'codePopup'`, Grid는 `editor: 'select'` 등 서로 다른 키를 각각 지정.
- **YAML의 `type`**은 맥락별로 의미가 다 다르다 (screen.type=화면유형, layout.type=전체레이아웃, sql.xxx.type=SQL종류, column.type=데이터타입, element.type=deprecated). 키 이름만으로 판단 금지, 상위 섹션을 반드시 확인.

## 10. AI가 자주 하는 실수 (핀포인트)

1. **`listener.button.save.click` 등록 누락** → 저장 버튼이 권한상 보여도 아무 일 안 일어남.
2. **`platform.post` Promise 혼용** → 구 `new Callback(fn)` 패턴과 `async/await` 섞임. 신규 코드는 `async/await` 통일.
3. **`setData(rows)` 단일 인자** → 서버 페이징 화면에서 totalCount 누락으로 페이저 미표시. `setData(rows, totalCount)`.
4. **`editor` vs `format` 혼동** — `editor: 'currency'`는 편집 시 입력 위젯, `format: 'currency'`는 표시 시 포맷팅. 조회 전용 컬럼은 `format`만, 편집 가능하면 둘 다.
5. **`FormaUtil.initSplit()` 누락** — split-h/split-v 레이아웃 후 호출 필수.
6. **address 위젯 필드 매핑** — `getData()`가 `{field}_zip`, `{field}_addr`, `{field}_detail`로 분해해 반환. DB 컬럼명에 맞게 변환하거나 DB 쪽을 맞춘다.
7. **코드 팝업 파라미터 전달** — `modal.show({buyYn:'Y'})` → 팝업에서 `FormaModal.getParam()`로 받아 서버 호출에 포함.
8. **`maxLength` 누락** — DDL이 `VARCHAR(N)`인 텍스트 컬럼은 YAML/JS에 `maxLength: N`을 반드시 박는다. FormaForm(text/password/textarea)과 FormaGrid(text/number/currency/textarea 에디터) 양쪽 지원. 빠뜨리면 사용자가 초과 입력 후 저장 시 서버 SQL 에러로만 반려되어 UX가 나빠짐.

## 11. FormaMDI (SPA 탭)

메뉴 클릭 시 `main.html`의 FormaMdi가 iframe 없이 div 기반으로 화면 로드. 화면 간 통신은 `window.parent.FormaMdi.openTab(...)` 또는 직접 JS 접근 가능. 상세: `forma.mdi.js` 주석.
