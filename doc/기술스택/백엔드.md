## 사용하지 않는 기술

| 기술 | 사유 |
|---|---|
| JPA / Hibernate | Map 기반 동적 SQL + MyBatis XML 로 ERP 도메인 표현. ORM 의 어그리거트 패턴이 화면-중심 ERP 와 잘 안 맞음 |
| Thymeleaf / JSP | 프론트 완전 분리(Static HTML + Vanilla JS + FORMA 컴포넌트). 서버 사이드 렌더링 미사용 |
| H2 / 임베디드 DB | PostgreSQL 단일 타깃. starter 의 `docker-compose.yml` 로 로컬 부트스트랩 |
| Webpack / Vite / npm | 프론트는 무빌드. `static/assets/js/framework/*.js` 를 직접 `<script>` |

## 데이터베이스

PostgreSQL 16 단일 타깃.

- **로컬**: `docker compose up -d` (호스트 15432 → 컨테이너 5432). 첫 기동 시 `src/main/resources/schema/*.sql` 자동 실행 → 테이블·코드·FRM_* PGM/메뉴/권한·admin 사용자(홍길동, BCrypt 비밀번호 `admin1!`) 시드 완료.
- **운영**: `application-prod.yml` 의 datasource 를 자기 PostgreSQL 로 가리키고 `FORMA_DB_USER`/`FORMA_DB_PASS`/`FORMA_JWT_SECRET` 환경변수 주입.

DDL 호환성: `BIGSERIAL`, `TEXT`, `WITH RECURSIVE`, `STRING_AGG`, `||` 문자열 연결 등 PostgreSQL 특화 문법을 적극 사용. 다른 DBMS 로 이식하려면 매퍼 XML 과 `schema/01-tables.sql` 양쪽을 재작성해야 한다.

## 데이터 액세스 패턴

**모든 DB 접근은 `FormaSqlSession` 을 통한다** — MyBatis 의 `SqlSessionTemplate` 을 감싸 (1) 데이터 권한 컨텍스트 자동 주입, (2) `resultType=map` 의 키를 `camelCase` 로 정규화한다.

```java
@Service
@RequiredArgsConstructor
public class ItemService {
    private final FormaSqlSession sql;
    private final String ns = "item";  // mapper namespace

    public List<Map<String, Object>> selectList(Map<String, Object> param) {
        return sql.selectList(ns + ".selectList", param);
    }

    @Transactional
    public void saveList(List<Map<String, Object>> rows) {
        for (Map<String, Object> r : rows) {
            String gstat = (String) r.get("gstat");
            if (Constants.GSTAT_INSERT.equals(gstat)) sql.insert(ns + ".insert", r);
            else if (Constants.GSTAT_UPDATE.equals(gstat)) sql.update(ns + ".update", r);
            else if (Constants.GSTAT_DELETE.equals(gstat)) sql.delete(ns + ".delete", r);
        }
    }
}
```

MyBatis 규칙:
- 매퍼 XML: `src/main/resources/mapper/{module}/{pgmId 소문자}.xml`, namespace 는 pgmId 소문자
- `parameterType="map"`, `resultType="map"` 기본
- `#{param}` 만 사용 (`${}` 는 sortField 같은 식별자에 한해 화이트리스트 검증 후)

## API 응답 규칙

```java
@FormaController(value = "/itm010", pgmId = "ITM010", description = "품목관리")
public class Itm010Controller extends BaseController {

    @PostMapping("/selectGrid1")
    public BaseResponse<?> selectGrid1(@RequestBody Map<String, Object> param) {
        return BaseResponse.Ok(service.selectGrid1(param));
    }

    @AddUserInfo  // 쓰기에만
    @PostMapping("/saveGrid1")
    public BaseResponse<?> saveGrid1(@RequestBody List<Map<String, Object>> rows) {
        service.saveGrid1(rows);
        return BaseResponse.Ok(rows);
    }
}
```

- 모든 응답은 `BaseResponse.Ok(data) / Warn(msg) / Error(msg)` 셋 중 하나
- `@FormaController` 가 `@RestController` + `@RequestMapping` 을 합쳐주고, `pgmId` 로 권한 매핑 자동 처리
- `@AddUserInfo` AOP 가 요청 파라미터에 `createdBy / updatedBy` 를 주입(쓰기 메서드 한정)

## 빌드 / 실행

```bash
./gradlew build              # 컴파일 + 테스트 + bootJar
./gradlew bootRun            # 개발 실행 (devtools 자동 재시작) → http://localhost:18080
./gradlew test               # 단위 + 통합 테스트. 통합은 Docker 가용 시에만 실제 실행
./gradlew test --tests com.forma.frame.util.PasswordPolicyTest  # 단일 테스트
./gradlew --stop             # gradle daemon 정리 (포트가 점유돼 있을 때만)
```

서버 관리 규칙은 `CLAUDE.md` 의 "서버 관리 규칙" 절 참조 — `taskkill` / `pkill` 로 java 프로세스 전체를 죽이지 말 것.
