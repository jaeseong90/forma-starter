# 설계서 기반 개발 프로세스

> **이 문서의 위상**: AI 코드 생성 워크플로의 개념 요약. 실제 명령/스킬 트리거는 `doc/AI-워크플로.md` 가 1차 소스고, YAML 문법은 `design/_schema_guide.yml` 이 1차 소스다.

## 핵심 흐름

FORMA 의 핵심 워크플로는 **자연어 요구 → YAML 설계서 → AI 코드 생성** 이다.

```
요구사항 (PL/사용자)
   │
   ▼  /new-screen 또는 forma-screen-workflow 스킬
design/screens/{화면ID}.yml         ← AI 생성, 사람이 검토
   │
   ▼  /yaml-to-code (방식 B 인 경우) 또는 YAML 런타임 엔진 (방식 A)
[방식 A] 그대로 사용                  [방식 B] 4파일 스캐폴드
  → screen.html 가 런타임 렌더링        ├── Controller.java
                                       ├── Service.java
                                       ├── mapper/{module}/{pgm}.xml
                                       └── pages/{module}/{PGMID}.html
```

방식 선택은 `doc/AI-워크플로.md` 의 "방식 A vs 방식 B" 절 참조. 한 줄 요약: 단일 테이블 CRUD + 표준 검색·권한이면 A, 트랜잭션 다중 테이블·계산·외부 API·필드 단위 readonly 가 필요하면 B.

## 디렉토리 구조

```
design/
├── _schema_guide.yml          # YAML 설계서 문법 가이드 (AI 가 참고)
├── _prompts/
│   ├── 00-generate-design.md  # 요구사항 → YAML
│   └── 01-generate-code.md    # YAML → 코드(방식 B)
└── screens/
    ├── DEMO_*.yml             # 학습용 예시 (편집·삭제 가능)
    └── {화면ID}.yml           # 신규 화면
```

> 과거 버전에는 별도 `_entities.yml`(전역 엔티티 정의) 가 있었으나, 현재는 각 YAML 설계서가 화면 + 필요한 테이블 정의를 자기 안에 담는 **single-file-per-screen** 구조다. 공통 코드/공통 테이블은 `src/main/resources/schema/*.sql` 가 단일 소스.

## YAML 설계서 최소 골격 (방식 A — list)

```yaml
screen:
  id: ITM010
  name: 품목관리
  type: list             # list / split-detail / master-detail / split-tab

search:
  - { field: item_nm, label: 품목명, widget: text }
  - { field: use_yn,  label: 사용여부, widget: select, code: USE_YN }

grids:
  grid1:
    editable: true
    checkable: true
    columns:
      - { field: ITEM_CD,    label: 품목코드, width: 100 }
      - { field: ITEM_NM,    label: 품목명,   width: 200, editor: text }
      - { field: UNIT_PRICE, label: 단가,     width: 120, editor: currency }

sql:
  tables:
    - { name: tb_item }
```

지원 화면 타입, 위젯/에디터, sql 블록 옵션 전체는 `design/_schema_guide.yml` 참조.

## 생성되는 산출물 (방식 B)

| 파일 | 경로 |
|---|---|
| Controller | `src/main/java/{basePackage}/domain/{module}/{PgmId}Controller.java` |
| Service | `src/main/java/{basePackage}/domain/{module}/{PgmId}Service.java` |
| MyBatis XML | `src/main/resources/mapper/domain/{module}/{pgmid}.xml` |
| 화면 HTML | `src/main/resources/static/pages/{module}/{PGMID}.html` (인라인 `<script>` IIFE) |
| (선택) DDL | `src/main/resources/schema/migrations/{YYYYMMDD}-{slug}.sql` |
| (선택) 코드 시드 | `src/main/resources/schema/02-codes.sql` 에 추가 |

**JS 파일 분리는 하지 않는다** — 화면 1개 = HTML 1파일 (스크립트 인라인). 자세한 관례는 `doc/프론트-패턴.md`.

## AI 자산

| 자원 | 위치 | 역할 |
|---|---|---|
| 스킬 (자동 트리거) | `.claude/skills/forma-screen-workflow/` | 자연어 → 방식 A/B 판정 → 설계 → 코드 → 리뷰 오케스트레이션 |
| 슬래시 커맨드 | `.claude/commands/{new-screen,yaml-to-code,review-screen}.md` | 단계별 명시적 실행 |
| 프롬프트 템플릿 | `design/_prompts/0[0-1]-*.md` | 직접 복사해 ChatGPT/Cursor 등에 붙여넣기 |
| YAML 스키마 | `design/_schema_guide.yml` | AI 가 YAML 작성 시 참조 |
| 학습용 예시 | `design/screens/DEMO_*.yml` | few-shot 예시 |
| 컨텍스트 | `CLAUDE.md` + `@CLAUDE.instance.md` | 모든 AI 세션 자동 로드 |
